Objectives

Part 1

사일로에서 E2E로

관점을 바꾸면 문제가 보이는 곳이 달라진다

Perspective

기능 사일로 vs E2E 가치흐름

😶 사일로 관점 (부서별)

영업팀: 견적 작성 ✓
    ⬇ (대기 2일)
구매팀: 발주 ✓
    ⬇ (대기 3일)
물류팀: 출고 ✓
    ⬇ (대기 1일)
재무팀: 청구 ✓

각 부서는 "내 일 끝" — 하지만 고객은 12일을 기다립니다.

🔭 E2E 관점 (가치흐름)

견적 → 발주 → 출고 → 청구
작업시간 합계: 6시간
리드타임 합계: 12일

⇒ 가치 창출 시간 2%

문제는 작업 속도가 아니라 흐름 사이의 빈 공간(대기·핸드오프)입니다.

Patterns

대표 E2E 흐름 3가지

Order-to-Cash

주문 → 이행 → 배송 → 청구 → 수금

영업·물류·재무를 관통. 현금 회수 속도의 원천.

Procure-to-Pay

구매 요청 → 승인 → 발주 → 검수 → 지급

요청 부서·구매·재무를 관통. 승인 대기의 온상.

Issue-to-Resolve

접수 → 분류 → 배정 → 처리 → 회신 · 사후관리

CS·개발·현장을 관통. 고객 경험과 직결.

생각해 보기여러분이 Module 1에서 고른 프로세스는 위 셋 중 어디에 가깝나요? 이름이 있으면 진단이 쉬워집니다.
Why Handoffs

문제는 왜 항상 '사이'에서 생기는가

  • 컨텍스트 손실 — 인수인계마다 정보가 증발하고, 다음 사람은 다시 묻습니다
  • 대기 행렬 — 받는 사람의 할 일 목록 맨 뒤에 줄을 섭니다
  • 책임 공백 — "넘겼다"와 "받았다" 사이, KPI의 사각지대
  • 양식 변환 — 시스템·엑셀·메일을 오가며 재입력이 발생합니다
경험칙핸드오프 1회당 지연·오류 비용이 붙습니다. 핸드오프 횟수 자체가 비용 지표입니다.

Tool 2

가치흐름지도(VSM) 5단계

  1. 제품군 선정 — 하나의 E2E 흐름만 고른다
  2. 현장 관찰로 현재 상태도 작성 — 규정문이 아니라 실제 흐름대로
  3. 각 단계에 시간 기록 — 작업시간(touch)과 대기시간(wait)을 분리
  4. 가치/낭비 표시 — 부가가치(VA) · 비부가가치(NVA) · 필요 비부가가치(RNVA)
  5. 미래 상태도 구상 — Module 3에서 본격 수행
주의규정문·매뉴얼로 그리면 "있어야 하는 절차"가 됩니다. 반드시 실제 담당자 인터뷰·관찰로 검증하세요.
Example · 예시

As-Is 단계 기록표 — 월간 마감

#단계담당작업시간대기의심 낭비
1각 팀 실적 취합 요청재무 A1h—수기 취합
2팀별 데이터 제출각 팀2h×82일대기·독촉
3양식 정합성 확인·수정재무 A6h—재작업
4이상치 검토재무 B4h0.5일수작업 대조
5보고서 초안 작성재무 B5h—반복 서식
6팀장 리뷰·승인팀장1h1.5일대기

작업시간 합계 ≈ 33h, 리드타임 ≈ 6일 — 가치 시간 비율 7%. 숫자가 보이면 고칠 곳이 보입니다. (예시 수치)

Tool 3

프로세스 마이닝 · 태스크 마이닝

⛏️ 프로세스 마이닝

시스템 이벤트 로그(케이스ID·활동·시각)에서 실제 흐름을 자동 복원합니다.

  • 발견: 실제 프로세스 시각화
  • 적합성: 규정 vs 실제 편차
  • 향상: 보틀넥·반복 루프 탐지

🖱️ 태스크 마이닝

PC 조작 기록으로 화면 단위 작업을 복원합니다. (복사·전환·재입력 탐지)

언제 쓰는가

  • 로그가 풍부하면 → 프로세스 마이닝 우선
  • 수기·엑셀 중심이면 → 인터뷰 + 태스크 마이닝
  • 둘 다 없으면 → 체크리스트 기반 관찰 (다음 슬라이드)
No Logs?

로그가 없을 때 — 인터뷰·관찰 체크리스트

담당자에게 묻기

  • "이 일을 시작하기 전에 무엇을 기다리나요?"
  • "한 건 처리하는 데 실제로 몇 분 걸리나요?"
  • "다시 하는 일은 얼마나 자주, 왜 생기나요?"
  • "규정과 다르게 처리하는 경우가 있나요?"
  • "이 단계가 사라져도 문제없다면?"

눈으로 확인하기

  • 엑셀 수기 장부 존재 여부
  • 시스템 간 복사·붙여넣기
  • "임시 파일" 폴더의 규모
  • 예외 처리의 즉흥성

Bottleneck

보틀넥과 큐의 신호

직관 — 리틀의 법칙

리드타임 = 진행 중 작업량(WIP) ÷ 처리율

줄(WIP)이 길면 리드타임이 깁니다. 보틀넥은 가장 긴 줄 앞에 있습니다.

현장의 큐 신호

  • 읽지 않은 메일·결재함이 쌓인 사람
  • "급한 건"이 끼어드는 빈도
  • 특정 담당자만 할 수 있는 단계
  • 마감 직전 폭주 패턴
원칙보틀넥이 아닌 단계를 개선하면 전체 리드타임은 거의 변하지 않습니다. 제약부터 푸세요.
실습 1 · 25분

우리 팀 As-Is 그리기

  1. 경계 설정 (5분) — SIPOC로 시작·끝·입출력 합의
  2. 단계 기록 (10분) — 워크시트 A에 단계·담당·작업시간·대기·의심 낭비 작성
  3. 지표 추정 (5분) — 리드타임·%STP·반려율을 현재 감각으로라도 기록
  4. Top 3 낭비 선정 (5분) — 가장 큰 낭비 3개에 별표

📄 워크시트 A · As-Is 매핑 — 인쇄본 또는 새 탭으로 열어 두세요. 정확한 숫자가 아니어도 됩니다. 구조를 채우는 것이 목표입니다.

Pitfalls

As-Is 진단의 흔한 실수

  • 그리면서 해결책부터 말하기 — 진단과 처방을 섞으면 관찰이 얕아집니다
  • 규정문 베끼기 — 실제 흐름과의 차이가 바로 개선 포인트입니다
  • 평균만 보기 — 최악 10% 케이스에 예외 처리 비용이 숨어 있습니다
  • 담당자 없이 그리기 — 실무자의 "비공식 노하우"가 프로세스의 실체입니다
Summary

Module 2 요약

  • 부서가 아니라 흐름을 본다 — 문제는 핸드오프 사이에 있다
  • SIPOC로 경계를, VSM으로 시간(작업/대기)을 기록한다
  • 로그가 있으면 마이닝, 없으면 인터뷰·관찰
  • 8대 낭비에 이름을 붙이고 6개 지표로 정량화한다
  • 산출물: As-Is 지도 + 낭비 목록 + Top 3
